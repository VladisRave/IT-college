# Шифрование данных в СУБД  
**Методы и инструменты шифрования для защиты конфиденциальной информации**

---

## Введение: Зачем нужно шифрование в базах данных?

**Рассмотрим реальную ситуацию:**  
База данных компании содержит личные данные клиентов, финансовые операции, медицинские записи. Если эта информация попадет к злоумышленникам, последствия будут серьезными:
- Финансовые потери
- Юридическая ответственность  
- Потера доверия клиентов

**Пример из практики:** В 2021 году произошла утечка данных из крупной компании. Хакеры зашифровали базу данных и потребовали выкуп. Компания не смогла восстановить данные, потому что не использовала собственное шифрование для защиты.

Шифрование — это не просто дополнительная опция, а необходимость в современном мире.

---

## Основные понятия шифрования

### Что такое шифрование?
**Шифрование** — это процесс преобразования читаемой информации (открытый текст) в нечитаемый формат (шифротекст) с использованием специального алгоритма и ключа.

**Простая аналогия для понимания:**  
- **Открытый текст** = "Пароль: 123456"  
- **Шифротекст** = "G8#kL9!pQ2*m"  
- **Ключ** = секретный код для преобразования

### Ключевые термины, которые нужно знать:
- **Шифрование (Encryption)** — процесс кодирования информации
- **Дешифрование (Decryption)** — процесс раскодирования информации  
- **Ключ (Key)** — секретная информация для шифрования/дешифрования
- **Алгоритм** — математическая формула преобразования данных

## Типы шифрования в системах баз данных

### 1. Симметричное шифрование
**Один ключ используется и для шифрования, и для дешифрования**

```sql
-- Простая аналогия: один ключ от замка (и закрыть, и открыть)
-- Примеры алгоритмов: AES, DES, 3DES
```

**Преимущества:** Высокая скорость работы, эффективно для больших объемов данных  
**Недостатки:** Проблема безопасной передачи ключа, если ключ украден - все данные можно расшифровать

### 2. Асимметричное шифрование  
**Используется два ключа: публичный и приватный**

```sql
-- Аналогия: кодовый замок (все могут закрыть, но открыть может только хозяин)
-- Примеры алгоритмов: RSA, ECC
```

**Преимущества:** Безопасный обмен ключами  
**Недостатки:** Медленнее симметричного шифрования, требует больше вычислительных ресурсов

## Методы шифрования в базах данных

### Метод 1: Шифрование на уровне столбцов
**Шифруются только определенные столбцы с конфиденциальными данными**

```sql
-- Пример: таблица пользователей
CREATE TABLE users (
    id INT PRIMARY KEY,
    name VARCHAR(100),
    email VARCHAR(100),
    credit_card VARBINARY(255),  -- зашифрованный столбец
    ssn VARBINARY(255)           -- зашифрованный столбец
);
```

**Когда следует использовать:**
- Номера кредитных карт
- Паспортные данные  
- Медицинские записи
- Пароли (в хешированном виде)

### Метод 2: Шифрование всей базы данных
**Шифруются файлы базы данных целиком**

```sql
-- Пример для MySQL
ALTER DATABASE mydb ENCRYPTION = 'Y';

-- Пример для PostgreSQL
CREATE DATABASE encrypted_db WITH ENCRYPTION = true;
```

**Когда следует использовать:**
- Финансовые системы
- Медицинские учреждения
- Государственные организации

### Метод 3: Прозрачное шифрование (TDE)
**Автоматическое шифрование данных "на лету"**

```sql
-- Пример для SQL Server
CREATE DATABASE ENCRYPTION KEY 
WITH ALGORITHM = AES_256  
ENCRYPTION BY SERVER CERTIFICATE MyServerCert;

ALTER DATABASE MyDatabase SET ENCRYPTION ON;
```

**Основные преимущества:** 
- Автоматическое шифрование всех новых данных
- Совместимость с существующими приложениями без изменений
- Пользователи не замечают процесса шифрования

## Практические примеры в различных СУБД

### Пример 1: MySQL - шифрование отдельного столбца

```sql
-- Создаем таблицу с зашифрованными данными
CREATE TABLE customers (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100),
    email VARCHAR(100),
    credit_card VARBINARY(255)
);

-- Шифруем данные при вставке
INSERT INTO customers (name, email, credit_card) 
VALUES (
    'Иван Петров', 
    'ivan@mail.ru',
    AES_ENCRYPT('1234-5678-9012-3456', 'мой_секретный_ключ')
);

-- Расшифровываем данные при чтении
SELECT 
    name,
    email,
    CAST(AES_DECRYPT(credit_card, 'мой_секретный_ключ') AS CHAR) as card_number
FROM customers;
```

### Пример 2: PostgreSQL - использование встроенного шифрования

```sql
-- Устанавливаем расширение для шифрования
CREATE EXTENSION IF NOT EXISTS pgcrypto;

-- Создаем таблицу
CREATE TABLE employees (
    id SERIAL PRIMARY KEY,
    name TEXT,
    salary NUMERIC,
    encrypted_salary BYTEA
);

-- Шифруем конфиденциальные данные
INSERT INTO employees (name, salary, encrypted_salary) 
VALUES (
    'Мария Сидорova',
    50000,
    pgp_sym_encrypt('50000', 'секретный_ключ_зарплата')
);

-- Расшифровываем для авторизованных пользователей
SELECT 
    name,
    CAST(pgp_sym_decrypt(encrypted_salary, 'секретный_ключ_зарплата') AS NUMERIC) as salary
FROM employees;
```

### Пример 3: SQL Server - прозрачное шифрование базы данных

```sql
-- Создаем главный ключ базы данных
CREATE MASTER KEY ENCRYPTION BY PASSWORD = 'StrongPassword123!';

-- Создаем сертификат для шифрования
CREATE CERTIFICATE MyTDECert WITH SUBJECT = 'TDE Certificate';

-- Создаем ключ шифрования базы данных
CREATE DATABASE ENCRYPTION KEY  
WITH ALGORITHM = AES_256  
ENCRYPTION BY SERVER CERTIFICATE MyTDECert;

-- Включаем шифрование для всей базы данных
ALTER DATABASE MyCompanyDB SET ENCRYPTION ON;
```

## Управление ключами шифрования

### Критически важные правила работы с ключами:
1. **Никогда не храните ключи в коде приложения**
2. **Используйте специализированные системы управления ключами (HSM, Key Vault)**
3. **Регулярно обновляйте и меняйте ключи шифрования**
4. **Разделяйте обязанности** (разные люди отвечают за шифрование и дешифрование)

### Пример неправильного подхода:
```sql
-- НИКОГДА НЕ ДЕЛАЙТЕ ТАК!
INSERT INTO users (password) 
VALUES (ENCRYPT('my_pass', 'key123'));  -- Ключ виден в открытом виде!
```

### Пример правильного подхода:
```sql
-- ПРАВИЛЬНЫЙ ПОДХОД: ключ хранится отдельно
SET @encryption_key = (SELECT key_value FROM encryption_keys WHERE id = 1);

INSERT INTO users (password) 
VALUES (AES_ENCRYPT('my_pass', @encryption_key));
```

## Распространенные ошибки и способы их избежать

### Ошибка 1: Избыточное шифрование данных
```sql
-- НЕПРАВИЛЬНО: шифруем все данные без разбора
CREATE TABLE products (
    id ENCRYPTED_INT,      -- Избыточно!
    name ENCRYPTED_TEXT,   -- Зачем шифровать название товара?
    price ENCRYPTED_FLOAT  -- Может быть избыточно
);

-- ПРАВИЛЬНО: шифруем только критически важные данные
CREATE TABLE products (
    id INT,                -- ID можно не шифровать
    name TEXT,             -- Название товара - публичная информация
    secret_discount_code ENCRYPTED_TEXT  -- А вот это уже секретно!
);
```

### Ошибка 2: Использование устаревших алгоритмов
```sql
-- НЕПРАВИЛЬНО: устаревший алгоритм шифрования
INSERT INTO data VALUES (DES_ENCRYPT('secret', 'key'));

-- ПРАВИЛЬНО: современный стойкий алгоритм  
INSERT INTO data VALUES (AES_ENCRYPT('secret', 'strong_key_256bit'));
```

### Ошибка 3: Неправильное хранение паролей
```sql
-- КАТЕГОРИЧЕСКИ НЕВЕРНЫЙ ПОДХОД!
CREATE TABLE users (
    username VARCHAR(100),
    password VARCHAR(100)  -- Пароли в открытом виде!
);

-- ПРАВИЛЬНЫЙ ПОДХОД: хеширование паролей с солью
CREATE TABLE users (
    username VARCHAR(100),
    password_hash VARCHAR(255)  -- Хеш пароля
);

-- При регистрации пользователя:
INSERT INTO users (username, password_hash) 
VALUES ('user1', SHA2(CONCAT('salt', 'user_password'), 256));
```

## Практическое руководство по выбору методов шифрования

### Рекомендации для начинающих:
1. **Начните с шифрования отдельных столбцов**
2. **Используйте алгоритм AES-256** - современный и надежный
3. **Шифруйте только самые важные данные:** пароли, платежные данные, персональные данные
4. **Обязательно хешируйте пароли** с использованием соли

### Простые правила выбора:
- **Пароли** → хеширование (SHA-256, bcrypt)
- **Платежные данные** → шифрование столбцов (AES-256)  
- **Медицинские данные** → шифрование всей базы данных
- **Корпоративные данные** → прозрачное шифрование + система управления ключами

## Практическое задание для закрепления материала

**Учебный сценарий:** Вы разрабатываете систему интернет-магазина. Необходимо защитить данные клиентов.

**Задача:** Спроектировать структуру базы данных с применением шифрования:

```sql
-- 1. Таблица пользователей (логины и хеши паролей)
-- 2. Таблица заказов (с шифрованными платежными данными)  
-- 3. Таблица профилей (с шифрованными персональными данными)

-- Требуется написать операторы CREATE TABLE с правильными типами данных
-- и комментариями, объясняющими выбор методов шифрования
```

**Критерии успешного выполнения:**
- Пароли хранятся в хешированном виде
- Номера банковских карт зашифрованы
- Персональные данные защищены шифрованием
- Ключи шифрования не хранятся в коде приложения

## Ключевые выводы

1. **Шифрование является обязательной мерой** для любой базы данных, содержащей конфиденциальную информацию
2. **Выбирайте метод шифрования в зависимости от потребностей:** шифрование столбцов, всей БД или прозрачное шифрование
3. **Защита ключей шифрования важнее защиты самих данных** — уделяйте этому первостепенное внимание
4. **Не шифруйте все данные подряд** — только информацию, имеющую критическую важность
5. **Используйте современные алгоритмы шифрования** (AES-256, SHA-256)

**Важно помнить:** Лучше потратить время на внедрение шифрования на этапе разработки, чем потом разбираться с последствиями утечки данных.
