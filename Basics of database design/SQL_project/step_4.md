### **Этап 4: Написание бизнес-запросов**

**Что делаем:** Пишем полезные запросы для анализа данных магазина.

**Практическое задание:**

1. **Топ-5 самых продаваемых товаров:**
```sql
SELECT p.name, SUM(oi.quantity) as total_sold
FROM order_items oi
JOIN products p ON oi.product_id = p.id
GROUP BY p.id, p.name
ORDER BY total_sold DESC
LIMIT 5;
```

2. **Выручка по месяцам:**
```sql
SELECT 
    DATE_TRUNC('month', o.order_date) as month,
    SUM(oi.quantity * oi.unit_price) as revenue
FROM orders o
JOIN order_items oi ON o.id = oi.order_id
WHERE o.status = 'completed'
GROUP BY month
ORDER BY month;
```

3. **Клиенты с наибольшим количеством заказов:**
```sql
SELECT 
    c.name,
    c.email,
    COUNT(o.id) as order_count,
    SUM(oi.quantity * oi.unit_price) as total_spent
FROM customers c
JOIN orders o ON c.id = o.customer_id
JOIN order_items oi ON o.id = oi.order_id
GROUP BY c.id, c.name, c.email
ORDER BY total_spent DESC;
```

1. **Проблема N+1 запросов:**
```sql
-- НЕЭФФЕКТИВНО: для каждого заказа отдельный запрос товаров
SELECT * FROM orders WHERE customer_id = 123;
-- затем для каждого order_id:
SELECT * FROM order_items WHERE order_id = ?;
```

2. **Решение - один запрос с JOIN:**
```sql
-- ЭФФЕКТИВНО: все данные за один запрос
SELECT o.*, oi.product_id, oi.quantity, oi.unit_price
FROM orders o
JOIN order_items oi ON o.id = oi.order_id
WHERE o.customer_id = 123;
```

### **Итоговый вывод**

**Связь с аппаратным обеспечением:**

- **Дисковые операции:** Индексы уменьшают полное сканирование таблиц (full table scan)
- **Оперативная память:** Кэширование часто запрашиваемых данных (товары, категории)
- **Процессор:** Сложные JOIN и агрегации требуют вычислительных ресурсов

**Ключевые принципы:**
- Проектируйте БД с учетом реальных сценариев использования
- Индексы - панацея и проблема одновременно (ускоряют чтение, замедляют запись)
- Мониторинг и анализ - основа принятия решений по оптимизации
